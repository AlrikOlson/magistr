A new chat should be able to find the work you already did. Magistr keeps
project records that Codex, Claude Code, or another connected agent can read.

Your code stays in your repository. You keep using your own coding agent
and model account.

## Your plan

The roadmap holds deliverables, priorities, dependencies, and acceptance
criteria. A piece being implemented has an objective and a more detailed
task plan.

For the game, the next agent can see that the rules are finished, the opponent
was checked, and the rematch work still needs attention. It can continue
unfinished work after reading the saved plan and current files.

## Your work history

Saved reasoning holds findings and decisions. In the game example, the useful
finding is that the short opponent policy can lose when it moves second.
The next agent can retrieve that evidence before replacing the search.

Important conclusions can be **pinned**. A reasoning **checkpoint** reviews
open questions and decisions; it is not a copy of the source.

Actions record work performed during a task. Checks keep verification results.
Artifacts point to the resulting files, commits, and other evidence. Saved
feedback can wait until you have time to investigate it.

## Work in your source

Magistr's tools let the agent find, read, and edit the actual project.
An edit can check that the file still matches the version the agent read,
so it does not silently overwrite a newer change.

For supported languages, edits are checked for new syntax errors before
writing. Changes made through these tools have a journal and can be undone.
A conflicting later edit is reported instead of silently discarded.

These protections apply to the tools that provide them. Keep using tests,
code review, Git, and your normal backups.

## Checking your work

An executed check records the command, exit code, output, and checked inputs.
A written review is a separate record.

A later session can inspect the result and whether it still applies.
[Checking the work](/docs/verification) covers focused checks, visual review,
and the full quality gate.

## Pick up in another session

Open the same project with Magistr connected and ask the agent to read the
saved work before continuing.

Codex and Claude Code can read the same Magistr records. This does not transfer
a conversation transcript or model settings between providers. The next agent
still needs to inspect the current code.

Magistr only knows what is recorded through it; it does not automatically
preserve every chat message.

## Agent sessions

Choose the model and permissions in your agent. Magistr's supported launch
options select the agent and settings for that run.

The agent's service handles its model requests. Keeping project records on
your Mac does not make those model requests run locally.

Different sessions can work on different areas. Each should read its selected
work and preserve changes made by the others.

## The desktop preview

The desktop is a separate preview available from source. It lets you open
projects, talk to an agent, return to saved conversations, and browse the
roadmap, reasoning, tasks, checks, activity, and feedback.

The roadmap shows actual work and its prerequisites. Reasoning investigations
have origins, branches, and conclusions; selecting a step opens its explanation.
Use the command line or your connected agent for the full planning and
change-review workflow.

**New session** starts a conversation. Return to an existing conversation to
recover your draft. **Stop** cancels the current turn. **Close session** ends
that session. Permission requests let you approve or decline an action.

Appearance can follow the system or stay light or dark.
[Try the desktop preview](/docs/installation#try-the-desktop-preview) explains
how to open it.

## Where your work is saved

Project settings and saved work live under `.magistr/` in the project.
Saved conversations also use Magistr's local data folder. Your agent keeps
its own conversation history.

Include project data when moving or backing up your work. Removing an agent
connection with `magistr remove` keeps saved work.
See the [removal instructions](/docs/installation#remove-setup-or-uninstall).
