description: The project records your next agent can read, and what they do and don't tell you.

Magistr connects to Codex or Claude Code through MCP, the protocol that lets
agents use tools. It keeps the work your agent records with it: the plan, the
reasons for changes, progress, and check results.

It doesn't automatically copy every conversation. Ask the agent to save the
decisions and findings you'll need next time.

## Your plan

The roadmap holds the work you've agreed to do, its priority, dependencies, and
how to check each result. The task being worked on has a more detailed plan and
a record of completed actions.

Have the agent read the saved plan before it starts. It can continue unfinished
work or help you choose what comes next. When you change direction, update the
roadmap so the next session follows the current plan.

## Your work history

Recorded findings explain what the agent investigated, which options it
considered, and why it chose an approach. New findings can correct old ones.

An important finding can be **pinned** so it's easier to retrieve.
A **checkpoint** marks a place in the work history to return to; it isn't a
backup of source files.

Feedback can be kept separately until you've investigated it and decided
whether it belongs on the roadmap.

## Changing source

Magistr's source tools let the agent find, read, and edit code. An edit can check
the file's fingerprint to detect changes made since the last read. For supported
languages, the tools also check for new syntax errors before writing.

Edits through these tools are journaled and can be undone. Those protections
don't apply to edits made elsewhere, and they don't establish that a feature
works. Keep using Git and review the actual changes.

## Checking your work

A command run through Magistr records its exit code and the source it checked.
A written review is recorded separately. A later session can tell what was
actually run and whether that result still applies to the current files.

Choose checks for the behavior you changed. An interface change may need a
build, interaction tests, and a visual review. A passing test doesn't establish
that a screen is readable.

Required checks need current passing results before a roadmap item can be
completed. When you need the full configured checks, run:

```sh
magistr validate
```

Set the commands during setup or in `.magistr/project.json`.
The [recorded example](/#workflow) shows a failing test, the fix, and the saved result.

## Agent sessions

Codex and Claude Code can read the same project's Magistr records. Resuming a
particular chat is a separate feature of the agent that ran it; Magistr doesn't
transfer transcripts or model settings between them.

Choose models and permissions in your agent. When Magistr launches a session,
its command-line options select the agent and supported settings for that run.

You'll need your own model account. The agent's service handles model requests;
local project records don't make those requests run locally.

## The desktop preview

The desktop is a separate preview available from source. Open projects, talk
to an agent, and return to saved conversations. Use the command line or your
connected agent for the full planning and change-review workflow.

**New session** starts a conversation. Switch between projects and conversations,
then return to recover your draft. Each session keeps its own work and
unanswered permission requests.

**Stop** cancels the current turn. **Close session** ends that session; quitting
the app closes its running work. Permission requests let you approve or decline
an action. Appearance can follow the system or stay light or dark.

See [Try the desktop preview](/docs/installation#try-the-desktop-preview) to open it.

## Where your work is saved

Project settings, plans, decisions, and progress live under `.magistr/` in the
project. Saved conversations also use Magistr's local data folder. Your agent
keeps its own conversation history.

Include the project data when moving or backing up your work.
`magistr remove` removes agent connections and keeps the saved work.
[Removal instructions](/docs/installation#remove-setup-or-uninstall) explain what stays.
