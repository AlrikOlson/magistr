# What Magistr remembers

A chat is useful while you're working. A project also needs to keep the plan,
the reasons behind a change, and what was checked. Magistr saves those records
so your next agent session can read them.

You keep using Codex or Claude Code. Magistr runs locally and connects to the
agent through **MCP**, the protocol that lets an agent call tools.
For practical examples, see [Work on a project](/docs/workflow).

## Your plan

The roadmap holds work you want to do: the result you want, its priority, what
it depends on, and how to check it. The current task has a more detailed plan
and a record of what the agent has done.

Ask your agent to read the saved plan before starting. It can continue unfinished
work, help you choose the next item, or revise the roadmap when the project
changes direction. Planning alone doesn't start implementation.

## Your work history

The agent can save what it found, the options it considered, why it chose an
approach, and what happened next. Ask it to record decisions that a future
session would otherwise have to work out again.

A later finding can correct an earlier one. An important finding can be
**pinned** to keep it easy to retrieve. A **checkpoint** marks a place to return
to while reviewing the work; it isn't a backup of your source files.

Feedback can be saved separately from the work you've decided to do.
That lets you investigate an idea before putting it on the roadmap.

These records are written as the agent works with Magistr. They aren't an
automatic copy of everything said in every chat.

## Changing source

Magistr's source tools let the agent find code, read it, and make changes.
A read includes a file fingerprint. An edit can use that fingerprint to catch a
file that changed after the agent read it.

For supported languages, the tools check for new syntax errors before writing
an edit. Changes made through these tools go into a journal that supports undo.

Those protections cover Magistr's source tools. They don't prove that the
feature works, and they don't cover edits made through other tools. Keep using
Git and review the changes.

## Checking your work

A check run through Magistr saves the command, exit code, and the source it ran
against. That lets a later session see what actually passed. If the relevant
source or settings change, the result may need to be checked again.

An agent's written review is recorded separately from a command Magistr ran.
Neither means every possible case has been tested. For interface work, inspect
the actual screens as well as running tests.

A roadmap item needs current passing results for its required checks before it
can be completed. A failed required check keeps the item open.

Choose checks that fit the change. For example, a small interface edit may need
a build, relevant interaction tests, and a visual review. Ask for the full
project checks when you need the broader check:

```sh
magistr validate
```

Set the commands during setup or in `.magistr/project.json`.
The [contact-list example](/#workflow) shows a failed test, the fix, and the
same test passing.

## Agent sessions

Your saved project work and your chat history are different things.
Codex and Claude Code can both read the project's Magistr records. Resuming
a particular conversation depends on the agent that ran it.

In an existing agent session, choose the model and permissions through that
agent. When Magistr launches a session, its command-line options select the
agent and supported settings for that run.

Magistr doesn't provide a model account. Your agent's service still handles
model requests, so keeping work locally doesn't mean the model runs locally.

## The desktop preview

The desktop is a separate preview available from source. You can open projects,
talk to an agent, and return to saved conversations. Use the command line or
your connected agent for the full planning and change-review workflow.

Choose **New session** to start a conversation. You can switch projects,
copies of a project, and conversations, then return and recover your draft.
Each session keeps its own work and unanswered permission requests.

Press Return to send, or Shift Return for a new line. **Stop** cancels the
current turn. Permission requests let you approve or decline an action.
**Copy conversation** copies the messages. **Close session** ends that session;
Quit closes the app and its running work.

Choose System, Light, or Dark under **Appearance**. See
[Try the desktop preview](/docs/installation#try-the-desktop-preview) to open it.

## Where your work is saved

Project settings, plans, decisions, and progress live under `.magistr/` in
your project. Saved conversations also use Magistr's local data folder.
Your agent keeps its own conversation history.

Keep the project data when moving or backing up your work. Removing an agent
connection with `magistr remove` keeps the project settings and saved work.
See [installation](/docs/installation#remove-setup-or-uninstall) for what removal
changes.
