---
title: Working with Magistr
description: Review a project, agree on the work, and keep improving it across sessions.
order: 2
---

Use Magistr from the agent you already work with. Bring it an unfinished project,
a feature idea, or something that needs fixing. The requests below are examples
you can adapt, after [connecting your agent](/docs/installation).

## Start by looking at what is there

For a project review, ask the agent to compare the code with the saved plan:

> What's left on this project? Read the code and the roadmap, find what isn't
> working well, and recommend the next changes in order of impact.

For a narrower review, name the problem: slow checks, confusing setup, an awkward
screen, or a feature that keeps breaking. Ask for research when the answer
depends on current tools or unfamiliar behavior. Have the agent save the findings
and explain why it recommends a particular approach.

A review should leave you with a decision you can act on. You can ask for the
changes immediately, or keep the findings until you're ready.

## Make a plan you can change

Ask the agent to turn the review into roadmap items. Each item needs a useful
result, a way to check it, and any work that must happen first.

> Make a plan from this review. Put the changes with the biggest effect first.
> Keep each item small enough to finish and verify.

Revisit the plan when the project changes. Tell the agent what no longer makes
sense and have it update the affected items. `$roadmap-refresh` in Codex or
`/roadmap-refresh` in Claude Code researches and revises the roadmap without
starting implementation.

For feedback you want to investigate later, ask the agent to save it.
`$signals` or `/signals` works through that feedback before you decide what to build.

## Finish one useful piece

Use `$next` in Codex or `/next` in Claude Code. The agent resumes interrupted
work first, or takes one ready roadmap item. It reads the code, makes the change,
runs the relevant checks, and commits the finished work.

If you want a different item, say which one:

> Work on the settings screen next. Finish it, check it at a narrow window size,
> and show me what changed.

For a direct fix, describe the defect and ask for the fix. A small request doesn't
need a separate roadmap. Failed checks still need to be resolved before the
affected work is called finished.

## Work through a longer stretch

Give a longer run a focus and a limit:

> Work through up to five items in the desktop track. Focus on the project
> picker. Verify and commit each finished item before continuing.

To start a fresh agent session for each item, run this from your project:

```sh
magistr next-loop --agent codex --max-iterations 5
```

Use `--agent claude` for Claude Code. Add `--track "Desktop"` to choose a track
with that name. The loop stops at its limit, when the track has no ready work,
or when it needs help to continue.

Inside a chat, `$next-loop` or `/next-loop` finishes one item and prepares a
handoff for the next session. Use the terminal command when you want Magistr
to manage those fresh sessions.

## Review the result and steer it

Try the changed feature. For an interface, have the agent open the actual screens
and inspect them at the sizes and appearances you support.

> Check the updated screens at desktop and phone sizes, in light and dark.
> Save and inspect the screenshots. Fix anything clipped or hard to read.

Tell the agent what you were trying to do and what felt wrong. Keep revising
until the agreed work is finished. Ask for checks that cover the change; a small
copy edit doesn't need every test in the project.

Be explicit about delivery. For example:

> After the checks pass, commit and push directly to main.

Use your project's own branch and review rules. At the end, ask for the commit,
what was checked, and anything that still needs attention.

## Pick up in a fresh session

Open the same project with Magistr connected:

> Read the saved work and current code. Continue the unfinished task from where
> we stopped, with the same scope and delivery instructions.

The next agent can read the roadmap, recorded decisions, progress, and check
results. It still needs to inspect current files: an earlier result may describe
older code.

Use `$next` or `/next` to resume roadmap work. For a longer run, keep the track
and remaining limit in the handoff. Codex and Claude Code can use the same
project records; their chat transcripts and model settings stay separate.

## Choose the right starting point

Plain requests work. These skills provide the project's usual instructions for
common tasks. Use `$name` in Codex or `/name` in Claude Code.

| When you want to… | Use |
| --- | --- |
| Research and revise the roadmap | `roadmap-refresh` |
| Investigate saved feedback | `signals` |
| Finish the next roadmap item | `next` |
| Finish an item and prepare the next session | `next-loop` |
| Run the full project checks | `validate` |
| Apply the project's usual workflow | `craft` |

Read [what Magistr remembers](/docs/concepts) for the difference between saved
project work and an agent's chat history.
