# Work on a project

You don't need a finished specification to start. Bring your agent a question,
an idea, a bug, or a part of the project that isn't working well. Magistr gives
the work somewhere to live as you figure it out.

This guide assumes you've [installed Magistr and connected your agent](/docs/installation).
The example requests below are things you can say in your own words.

## Start by looking at what is there

Before asking for code, ask the agent to understand the project. A useful first
request is:

> Read the code and the saved plan. What already works, what's unfinished, and
> what would you work on next? Explain your recommendation before changing anything.

For an unfamiliar problem, ask for research too. Have the agent check its ideas
against the code and current sources, explain the tradeoffs, and save the useful
findings. That gives the next session more to go on than a conclusion with no explanation.

You can also ask for a focused audit: a slow screen, confusing setup, unreliable
tests, or an awkward part of the architecture. Name the problem you want solved.

## Make a plan you can change

Once you know where to go, ask the agent to put the work on the roadmap.
Each item should describe a useful result and how you'll know it works.
If one item depends on another, have the agent put them in order.

> Turn this into a plan. Keep the first version small enough to finish and use.
> Put the interface work first, and explain what can wait.

The roadmap is allowed to change. If a better approach appears, ask the agent to
check it, update the affected work, and retire the old idea. You can use
`$roadmap-refresh` in Codex or `/roadmap-refresh` in Claude Code for a research
pass that updates the plan without starting implementation.

For feedback you want to save for later, ask the agent to record it. Use
`$signals` or `/signals` to investigate saved feedback. Researching a suggestion
doesn't automatically make it the next thing to build.

## Finish one useful piece

When you're ready to build, use `$next` in Codex or `/next` in Claude Code.
It resumes interrupted work first, or takes one ready item from the roadmap.

The agent reads the current code, makes the change, runs the relevant checks,
records the result, and commits the finished work. If a check fails, the work
still needs attention. Ask what failed and have the agent fix the cause.

Be specific when the default next item isn't what you want:

> Work on the settings screen next. Finish that item, check it at a narrow
> window size, and show me the result.

For a direct fix, describe the problem and ask the agent to fix it.
You don't have to turn every request into a large roadmap.

## Work through a longer stretch

Name the area and give the work a limit. For example:

> Work through up to five items in the desktop track. Keep the focus on the
> project picker. Verify and commit each finished item.

To have Magistr start a fresh agent session for each item, run this from your
project's terminal:

```sh
magistr next-loop --agent codex --max-iterations 5
```

Use `--agent claude` for Claude Code. Add `--track "Desktop"` to stay within a
track with that name in your roadmap. The loop stops at its limit, when there
is no ready work in the chosen track, or when it needs help to continue.

Inside an existing chat, `$next-loop` or `/next-loop` finishes one item and
prepares a handoff. You open the next session to continue. Use the command-line
loop when you want Magistr to manage those fresh sessions.

## Review the result and steer it

Ask to see the part that changed. For code, that might be the diff and the test
output. For an interface, use it and look at screenshots of the relevant screens.
A passing test doesn't tell you whether a layout feels crowded or a label makes sense.

> Open the updated screens at desktop and narrow sizes. Check both appearances.
> Save the screenshots, inspect them, and fix anything clipped or hard to read.

Give concrete feedback: what you were trying to do, what you saw, and what felt
wrong. The agent can revise the current work or add a follow-up to the roadmap.

Ask it to finish the agreed work before moving on. A useful wrap-up says what
changed, what was checked, what remains uncertain, and which commit contains it.
Tell the agent when you want commits pushed, a pull request opened, or a deployment;
those are choices for your project.

## Pick up in a fresh session

Open the same project with its Magistr connection and ask:

> Read the saved work and the current code. Tell me where we stopped, then
> continue the unfinished task. Keep the same scope.

The new session can read the roadmap, recorded decisions, completed actions, and
check results. It should inspect the files too; a saved result may belong to an
older version of the code.

Use `$next` or `/next` to resume roadmap work. When handing off a longer run,
keep the chosen track and remaining limit in the handoff. You can use either
Codex or Claude Code with the same project's Magistr records. Their chat
transcripts and model settings remain separate.

## Choose the right starting point

You can ask in plain language. These shortcuts are available when you want the
project's usual instructions for a particular kind of work.

Use `$name` in Codex or `/name` in Claude Code: for example, `$next` or `/next`.

| What you want to do | Skill |
| --- | --- |
| Research and revise the roadmap | `roadmap-refresh` |
| Investigate saved feedback | `signals` |
| Finish the next roadmap item | `next` |
| Finish an item and hand off a longer run | `next-loop` |
| Run the project's full quality gate | `validate` |
| Apply the project's usual way of working | `craft` |

For ordinary changes, ask for checks that cover the affected behavior. Use the
full quality gate when you want the broader check.
