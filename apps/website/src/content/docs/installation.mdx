# Installation

The first release targets **Apple Silicon macOS**. Magistr v{version} is still in preview; npm and Cargo registry packages are not published yet. Building the preview requires access to the [repository](https://github.com/AlrikOlson/magistr). The desktop is a separate development build.

> **Permission and privacy boundary**
>
> Magistr runs locally and keeps its state in the project. Your agent runtime keeps its own credentials and operating-system permissions; Magistr does not sandbox it. Review commands and generated files before using it on a sensitive checkout.

## Install the preview

Requires macOS 15 or later on Apple Silicon, Git, Rust 1.95 or later, and the macOS command-line build tools. Install and sign in to Codex or Claude Code separately.

```sh
git clone https://github.com/AlrikOlson/magistr.git
cd magistr
cargo install --locked --path crates/magistr-cli
magistr --version
```

Cargo installs `magistr` into its binary directory, usually `~/.cargo/bin`. Add that directory to your PATH if the command cannot be found.

Once the registry packages are published, this page will include npm and Cargo installation commands. The prepared npm package includes the native executable and requires no Rust, Bun or source checkout.

## Set up your project

In the project you want to work on, run:

```sh
cd ~/src/my-project
magistr init .
```

Setup detects your stack, lets you choose one or more agents, and shows the verification commands and proposed file changes before applying them. **Only selected integrations are generated.** Existing custom settings, instructions, unrelated MCP servers and saved work are preserved.

Setup checks the MCP connection and reads the project context. It finishes with a starter prompt to inspect the project and propose a plan. **Setup does not start implementation.** If an agent is unavailable, follow the reported installation or sign-in instructions; its setup files can still be prepared.

To preview a specific selection without writing files:

```sh
magistr init . --agent codex,claude --dry-run
```

Use `--yes` instead of `--dry-run` to accept the setup defaults without prompts. Repeating initialization preserves the project's identity, work and custom settings.

## Connect Codex

Choose Codex during setup, or prepare only its integration:

```sh
magistr init . --agent codex --yes
./.codex/run
```

The launcher loads the project's instructions, skills and Magistr connection. Start a new agent session after changing setup.

## Connect Claude Code

Choose Claude Code during setup, or prepare only its integration:

```sh
magistr init . --agent claude --yes
claude
```

Claude Code reads the Magistr connection from `.mcp.json` and the project instructions and skills from `CLAUDE.md` and `.claude/`. Approve the project's MCP connection when Claude Code prompts you.

## Connect another agent

Choose **Another MCP agent**, or run:

```sh
magistr init . --agent portable --yes
```

This writes standard MCP configuration to `.mcp.json` and instructions to `.magistr/instructions.md`. If your agent does not read those files, copy the Magistr connection into its MCP settings and load the instructions.

The connection launches `magistr mcp --dir /path/to/project`. It provides project context, source search, reading and editing, planning, recorded progress and verification through one server.

Optional project instructions are also available with `--agent cursor`, `copilot`, `cline`, `windsurf` or `aider`. Select multiple agents with commas or repeated `--agent` options.

## Check or repair setup

```sh
magistr doctor .
magistr repair . --dry-run
magistr repair .
```

`doctor` reports missing setup, malformed configuration, unavailable agents and connection failures with recovery commands. Repair shows its proposed changes and preserves customized files and unrelated connections. Starting the MCP server does not repair project files automatically.

Project settings live in `.magistr/project.json`, including verification commands and required checks. Magistr keeps the roadmap and recorded work inside `.magistr/`.

## Upgrade the preview

From your Magistr source checkout, update and reinstall:

```sh
git pull --ff-only
cargo install --locked --path crates/magistr-cli --force
```

Then run `magistr doctor .` and `magistr repair .` in each project to review and refresh its integration.

## Remove setup or uninstall

Preview and remove the generated integration in each project:

```sh
magistr remove . --dry-run
magistr remove .
```

Removal keeps project settings, recorded work, customized files and unrelated MCP connections. Review the report for any files preserved. To uninstall the executable after removing the integrations:

```sh
cargo uninstall magistr-cli
```

## Start work when you are ready

Ask your agent to inspect the project and propose a plan first. Use `$next` in Codex or `/next` in Claude Code when you want to implement one ready roadmap item. The skill resumes interrupted work before starting another item.

From the command line, `magistr next` runs one work item. `magistr next-loop --max-iterations 5` continues through up to five fresh agent sessions. `magistr validate` runs the configured checks.

## Try the desktop development build

The desktop is separate from the first CLI release. On macOS, open **Launch Magistr.command** in the source checkout. Building it requires Rust, Node.js and the [platform build prerequisites](https://v2.tauri.app/start/prerequisites/). Development packages are not publicly signed or notarized.

See the [development guide](https://github.com/AlrikOlson/magistr/blob/main/docs/development.md) for build and packaging commands, or continue with [concepts](/docs/concepts).
