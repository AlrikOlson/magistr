# Architecture

Magistr is a Rust workspace. Project state lives in the project; several clients read and write it through one owner.

| Crate | Owns |
| --- | --- |
| `magistr-cli` | The `magistr` command, project setup, the session host and the tool server |
| `magistr-domain` | Identities, run rules, policy and verification values |
| `magistr-application` | Project-scoped use cases and the ports they need |
| `magistr-engine` | Sessions, workflow policy, quality gates and the native workflow state |
| `magistr-workflow` | The roadmap, reasoning, execution and signal families behind the tools |
| `magistr-workspace` | Source navigation, verified edits and the workspace owner |
| `magistr-cockpit` | The shared interface model: state, updates, layout, widgets and commands |
| `magistr-tui` | Terminal input, graphics protocols, pixel compositing and the runtime |
| `magistr-mcp` | The Model Context Protocol tool definitions and request handling |

## Boundaries

The cockpit owns the model, the view and the typed commands; it knows nothing about terminal protocols. The terminal crate owns raw mode, input decoding, graphics negotiation and compositing. Pixel rendering — the dependency graph, the reasoning graph, the icons — is an enhancement over the cell rendering, which stays complete on a plain terminal. The desktop interface uses the shared model and is independent of the terminal crate.

Every process that writes a project's state does so through the one admitted owner; other clients attach to it. Checkpoints and pins travel through typed commands and ports, never through the renderer.

For the full map, including the client inventory and the durability rules, read the [repository architecture overview](https://github.com/AlrikOlson/magistr/blob/main/docs/architecture/overview.md) and the [terminal architecture](https://github.com/AlrikOlson/magistr/blob/main/docs/architecture/terminal.md).
