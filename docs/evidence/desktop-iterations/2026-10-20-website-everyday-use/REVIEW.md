# Website copy: everyday project work

User task: rewrite the website and public documentation around how the owner actually uses Magistr in Codex and Claude Code.

## Research and scope

The review scanned all 302 locally available session JSONL files: 110 Codex and 192 Claude Code files, with no parse errors. Of these, 218 contained actual Magistr or predecessor workflow tool calls. After excluding sidechains, interruptions, generated handoffs and staged screenshot demos, the extraction contained 395 relevant user requests (222 Codex, 173 Claude Code); 118 generated handoffs were excluded. The review used substantive requests and recurring patterns, not a manual line-by-line reading of every tool result. Raw histories and private project details are not included here.

The recurring pattern was to inspect the code, research options, revise the roadmap, run bounded work, check the actual result, commit completed work, and continue in a fresh session. The new copy follows that pattern. Examples are newly written illustrations rather than quotations from private chats.

The change covers the landing page, all published website guides, navigation, search messages, 404 page, metadata and social preview, plus the repository README and getting-started guide. The existing contact-list demonstrations keep their original screenshots and transcript excerpts. Contributor architecture and API references remain technical references.

Claims were checked against the native next/next-loop, roadmap-refresh and signals skills; next-loop CLI help; current desktop documentation; and the project-upgrade owner and callers. The old explicit-repair-only upgrade claim was corrected to match automatic upgrades.
