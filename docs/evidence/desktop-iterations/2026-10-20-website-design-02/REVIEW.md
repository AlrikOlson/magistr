## Findings and checks

The initial [iteration 01](../2026-10-20-website-design-01/REVIEW.md) failed for an oversized browser focus outline and noninteractive text styled as full-session links. Both are corrected here: the focused heading has a restrained violet outline; full-session captions are real anchors to original PNGs. The mobile menu is in page flow, closes on Escape and same-page navigation, and restores focus when changing layout. No clipping, overlap or unintended empty geometry was observed. There are no connection diagrams to assess.

The neutral light/dark surfaces and violet emphasis match the actual app. Introductory copy explains saved plans, work history and checks in familiar language. Registry packages remain explicitly unpublished; the desktop remains a separate source preview. No product data or screenshot content was invented.

Focused recorded gates passed: Astro build/content checks plus 14 public-content regression tests (receipt 34c1b4c7-f5d9-4630-a867-8e74e8131101); four-profile WebKit interactions/captures (receipt 88aef501-0ba8-4779-a85f-0d4bdeb2cbeb). Scenarios include 320px reflow, theme persistence, image links, search, keyboard skip link, 44px header controls, primary/control contrast, code wrapping and menu Escape/anchor/resize recovery.

Research used the [WAI disclosure navigation example](https://www.w3.org/WAI/ARIA/apg/patterns/disclosure/examples/disclosure-navigation/) for semantic navigation and focus recovery. This is a heuristic visual review, not a user study or accessibility certification. Headless WebKit does not verify native assistive technology, every text enlargement setting, other browser engines or foreground OS input. Terminal screenshots are thumbnails with full-size links. Deployment is verified separately.
