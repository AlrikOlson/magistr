## Research and delivery boundary

The upgrade follows the official [Astro 7 guide](https://docs.astro.build/en/guides/upgrade-to/v7/) and [Astro 6 guide](https://docs.astro.build/en/guides/upgrade-to/v6/), including current Node requirements and content-schema imports. The [Astro AVIF advisory](https://github.com/withastro/astro/security/advisories/GHSA-26w7-cxv4-gfx2) is addressed by the resolved Astro/Sharp releases. Removing the unused code-rendering plugin also removes its vulnerable selector-parser chain; see [GHSA-rj75-hqrm-r3gf](https://github.com/advisories/GHSA-rj75-hqrm-r3gf). This website builds static files; it does not expose Astro's image processing as a server endpoint.

The installation guide now matches selected integrations, an explicit planning boundary, Codex/Claude/portable connection setup, doctor, repair, upgrade and removal. It states macOS 15+ on Apple Silicon and that npm/Cargo packages remain unpublished. The home page points to these instructions. Version display continues to read the canonical package version rather than adding another maintained value.

Deployment output is `apps/website/dist`. Existing hosting is Cloudflare Pages at `magistr.dev`; the coordinating session owns deployment and post-deployment checks. No deployment, repository visibility change, registry publication or release declaration was performed by this website task. After the actual registry release, replace the preview-only installation/upgrade copy with verified registry commands and rerun the release-stage public check.

Limitations: headless WebKit does not verify native Safari/OS focus preferences, assistive technology or the desktop application. The skip-link test programmatically focuses the link before keyboard activation; it does not prove every system's Tab-order preferences. Plausible analytics is stubbed during browser testing. The site still relies on external font availability. Repository/support-link public availability is owned by the publication gate and is not inferred from a local build.
