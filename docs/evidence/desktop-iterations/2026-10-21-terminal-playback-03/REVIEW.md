# Terminal playback — iteration 03

Task: make the recorded Bevy build feel like a terminal session, with scrubbing and useful annotations; keep syntax and diff highlighting readable across the website.

Verdict: **PASS.** Opened and inspected all 28 original full frames listed below. The timeline now belongs to the terminal column. On phones it occupies its own row, with playback controls immediately below; the 320px frame keeps Codex and the recording label on one line. The copy button and confirmation use the active theme. Rust in compiler diagnostics is highlighted while preserving the original output.

[Browser results and source identity](browser-checks.json) record capture times, exact viewport sizes, appearance, WebKit version and source SHA-256 hashes. All interaction checks passed, including rapid seeking, keyboard playback, exact source copying, reader focus, theme changes, project views, all seven guides, no-JavaScript transcript and unavailable-recording recovery. Build/publication tests and the screenshot gate also passed.

This iteration changes the terminal frame, transport, installation copy controls and compiler-output highlighting. The source/diff readers, native roadmap/reasoning visuals and guide code blocks retain the inspected passing layout in [iteration 02](../2026-10-21-terminal-playback-02/REVIEW.md); no old capture is presented as a new capture. The original failing mobile and copy states remain there for comparison.

Review limitations: headless WebKit only, reduced motion, no native OS input or assistive-technology certification. Clipboard content was checked with a browser stub. Terminal text wraps at cell boundaries; narrow views show less code at once and retain scrollback and the full reader. Compiler readers scroll for long output. These are intentional, readable scrolling states. No open layout, contrast, clipping, overlapping-control or graph-attachment defects remain in the changed areas.
