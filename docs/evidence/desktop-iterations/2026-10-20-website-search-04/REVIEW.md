The previous search-03 capture is retained with its failed test receipt: the supposedly unmatched fixture contained “magistr” and correctly matched the index. This run uses a verified unmatched query. No previous image was overwritten.

The production failure was traced to eager Pagefind initialization and an uncaught asynchronous metadata request during navigation. The owner is the documentation layout. Pagefind documents lazy initialization through search in its [JavaScript API](https://pagefind.app/docs/api/); the implementation now follows that lifecycle and handles each query's result or failure.

This is headless browser evidence. Native OS input, assistive technology, mobile hardware and non-WebKit browser behavior were not exercised. No graph or connector geometry is present in the changed search states. Production checks and production captures are recorded separately after deployment.
